# Capability Relationship Matrix

Only relationships actually investigated in the `system-intelligence` work are listed.
Verification uses the contract's classification: **VERIFIED** (the path ran or is proven by
tests executed for this change), **CONFIGURED** (code/settings establish the connection; not
re-executed end to end here), **AVAILABLE** (exists; relationship untested), **BROKEN**
(demonstrated failure), **UNAVAILABLE**.

| Capability | Related capabilities | Relationship | Verification | Limitations |
|---|---|---|---|---|
| `SessionSystemPrompt.make/render` | Every session model request | Renders `system.txt` and appends the Truthfulness + Capability-awareness contracts; the static half of every system prompt | VERIFIED — unit tests (`session-system-prompt.test.ts`) assert both contracts exactly once for multiple tool sets and custom templates | Prompt-level enforcement only |
| `SessionModelRequest.baseTranscript` | Custom agent system prompts | Appends whichever global contracts a custom prompt does not embed; a prompt embedding both is used verbatim | VERIFIED — unit tests cover neither/one/both embedded, plus subagent-mode agents | Dedupe keys on the exact contract headers; a paraphrased copy in a custom prompt would not be recognized |
| Runner (`session/runner/llm.ts`) | Primary, specialized, subagent, team-worker, orchestrator sessions | Builds every step's request through `baseTranscript`; subagents and team workers are ordinary child sessions, so the contracts propagate without a separate path | VERIFIED — construction path read end to end; subagent tool creates child sessions via `Session.Service` | Behavioral compliance is model-dependent |
| Compaction (`session/compaction.ts`) | Session history, summary model requests | Compaction requests are built through the same `baseTranscript`; the system prompt is rebuilt per request, so contracts survive compaction and resume | VERIFIED — `session-native-compaction` 6/6; recalibrated fit scenario passes; full runner failure set identical to clean `main` | The fit scenario's fixture window is calibrated to prompt size and must grow if the static prompt grows materially |
| Generate (`session/generate.ts`) | One-shot generation requests | Same `baseTranscript` construction | CONFIGURED — call site read; no dedicated new test | — |
| Model-lab optimize plugins (`plugin/optimize.ts`) | Model-specific prompt templates (OpenAI, Anthropic, DeepSeek, Kimi, Arcee, Meta) | For agents without a custom system, replaces or appends the system prompt with `render(template, tools)`, thereby inheriting both global contracts | CONFIGURED — code path read; the plugin's own test expectations are stale since the PR #21 rename (4 failures, identical on clean `main`) | Plugins skip agents with custom system prompts (those are covered by `baseTranscript` instead) |
| Title generation (`session/title.ts`) | Session naming | Uses the title agent's `system` verbatim or nothing; receives **no** global contracts | VERIFIED (the bypass itself) — `title.ts` system construction read | Intentional exclusion: one-shot utility, no tools, no capability composition; already bypassed Truthfulness before this change |
| ACP / Mini surfaces | Core sessions | Both drive core sessions; their model requests go through the runner and `baseTranscript` | CONFIGURED — session-based construction confirmed; surfaces not separately re-run | No surface-specific prompt path exists to patch |
| `SessionContext.select` | Tool snapshot, instructions composition | Builds the available-tool inventory (advertised + Code Mode + lazy) from the permission-narrowed snapshot (agent + session permissions merged) and feeds it to the guidance producers | VERIFIED — code path read; guidance filtering unit tests | Inventory is per-step; a tool installed mid-session appears on the next selection |
| `ToolGuidance` | MCP servers (context7, desktop-commander, git, memory, sequential-thinking, rea-anything, browser stacks), `question`, `mcp_forge` | Intent→tool routing lines are rendered only when a matching tool is actually available, including MCP namespace prefix matches (`context7` matches `context7_*`) | VERIFIED — new unit tests: subset availability, prefix matching, empty inventory renders nothing | Routing is advisory text; execution permissions are enforced by the tool layer, not the guidance |
| `CodeModeInstructions` | Code Mode catalog, `execute`/`search` | Renders the live catalog summary with add/remove diffs and an explicit "no Code Mode tools" state | CONFIGURED — producer read; covered indirectly by instruction suites | Not re-executed end to end in this change |
| `McpInstructions` | Connected MCP servers, session permissions | Lists instructions only for servers the session may use; gates on the `execute` permission; emits add/remove updates | CONFIGURED — producer read | Server *instructions* being listed does not prove the server's tools succeed at call time |
| `HubInstructions` | Hub recipes, session permissions | Availability-resolved and permission-filtered recipe guidance | CONFIGURED — producer read | — |
| `SkillInstructions` | Installed skills, `skill` tool | Lists real installed skills or an explicit empty state; removal notices when skills disappear | CONFIGURED — producer read | — |
| `core/skill-catalog` builtin | `skill_catalog` tool (SkillsMP) | Instruction tells the agent to consult the catalog at task start — previously injected unconditionally, advertising the tool even to sessions whose permissions removed it | VERIFIED — gap demonstrated by code inspection; fix gated on the session inventory; new regression test in `builtins.test.ts` (present iff `skill_catalog` is available) | Callers that pass no inventory keep the historical always-on behavior |
| Subagent tool (`tool/plugin/subagent.ts`) | Agent registry, permissions, child sessions | Spawning checks agent mode, permission (`subagent` action per agent), and depth limit (default 1, `experimental.subagent_depth`); the tool's own description is dynamically extended with the permitted subagent list via context/compaction/generate hooks | CONFIGURED — plugin read end to end | Depth default of 1 means nested subagents need explicit configuration |
| Plugins (general) | Tool registry, skill system, command palette | Plugin capabilities register as tools/skills/commands and therefore appear in the existing dynamic inventories; there is no separate plugin inventory producer | AVAILABLE — registration architecture read (`tool/AGENTS.md`, internal plugin list) | A plugin that registers nothing model-visible is invisible to the agent by design |
| Provider fallback / routing | Prepared model requests | Fallback reuses the same prepared request; both contracts live in its system parts, so a provider switch cannot drop them | CONFIGURED — request pipeline read (`model-request.ts` prepare) | Provider-specific prompt plugins may replace the template half, but `render()` re-appends both contracts |
