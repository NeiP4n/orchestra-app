# Передача проекта: Orchestra Harness

Файл для того, кто продолжит работу над программой (человек или модель внутри самой Orchestra).

## Что это
Свой агент для терминала на Rust. Публичный проект с открытым ядром, лицензия MIT. Вырос из форка opencode, но новый код его не использует. Старый TypeScript лежит в `packages/` как эталон и будет удалён по мере переноса.

## Принципы (от автора)
- Лимитов самой программы нет по умолчанию (шаги, таймауты). Старое поведение: `ORCHESTRA_ENFORCE_LIMITS=1` (только старый TS-код).
- Модель получается любым законным способом через «транспорты»: свой ключ (OpenAI-совместимый API), официальный CLI, в котором человек уже вошёл, буфер обмена с человеком в цикле. Нельзя: чужие client-id, подделка клиента, автоматизация чужих сайтов, обход лимитов.
- Интерфейс: 2–3 цвета, без градиентов, только контуры, статичный дизеринг (`░▒▓`), анимация позже; один общий тик, не мешает вводу.
- Ничего не удалять из старого `opencode-pp\src` (там чужая работа и живой сервис).

## Карта
- `crates/orchestra-kernel`: `Transport`, `Pool` (failover при лимитах), `run()` (цикл агента без потолка, параллельные инструменты, сжатие контекста).
- `crates/orchestra-session`: журнал сессий в `.jsonl`, восстановление после падения, `drive()`.
- `crates/orchestra-memory`: память global/project/session с бюджетом (`recall`), закреплённые записи.
- `crates/orchestra`: CLI. Транспорты: `transports.rs` (OpenAI-совместимый, «человек»), `clipboard.rs`, `cli.rs` (мост к официальным CLI), `presets.rs` (gemini, groq, openrouter, cerebras), `config.rs`, `tools.rs` (shell, read_file, write_file, list_dir, remember).
- `packages/kernel`: TypeScript-версия ядра, эталон поведения (те же сценарии, что в Rust-тестах).
- `docs/THEORIES.md`: экспериментальные гипотезы с критериями проверки. `docs/START.md`: установка и запуск.

## Как собирать и проверять
Нужны Rust (GNU-цепочка `stable-x86_64-pc-windows-gnu`) и mingw-w64 (WinLibs, ставится через winget) в PATH.
```
cargo test --workspace
cargo build --release -p orchestra
.\installer\install.ps1
```
Если установленный `orchestra.exe` занят запущенной программой: переименовать его в `orchestra.old.exe` и скопировать новый. Тесты, использующие настоящий буфер, помечены `#[ignore]` (`cargo test -- --ignored`).

## Состояние и что дальше
Готово: ядро, сессии, память, CLI, транспорты (ключ, человек, буфер, мост к CLI), установщик.
Не готово: полноэкранный TUI на `ratatui` (по правилам интерфейса выше), OAuth со своими client-id, обмен квотой между своими устройствами (P2P), сервер/протокол поверх Rust-ядра, удаление старого TypeScript.
Проверено на реальных моделях: ничего (ключей не было); транспорты проверены на тестовом сервере и поддельных CLI.
Известно: Gemini CLI для «individuals» больше не поддерживается Google (UNSUPPORTED_CLIENT); бесплатный Zen работает только внутри OpenCode и сейчас исчерпан лимитом.
