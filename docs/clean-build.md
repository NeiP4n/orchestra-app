# Сборка с нуля / репетиция сдачи — `script/clean-build.sh`

Перед сдачей проект собирается в чистом окружении (идея #16 из лучших 25
общего подхода): свежий worktree, установка зависимостей, сборка, проверки
пакетов — без локальных путей, кэшей и недоговорённостей рабочего дерева.
«У меня работает» больше не проходит.

## Запуск

```sh
script/clean-build.sh [--ref <ref>] [--steps install,build,typecheck,lint,test] [--smoke] [--tests] [--keep] [--record [journal]]
script/clean-build.sh --smoke        # быстрая проверка: install + typecheck core
script/clean-build.sh --tests        # плюс тесты packages/core (область test/autoloop)
```

По умолчанию ref — HEAD, шаги — `install,build,typecheck,lint`.
Сборка — серверный стек: schema, protocol, core, server, cli.
Typecheck — `bun script/check.ts --all` (все активные пакеты).

## Правило сдачи

Сдача требует записанного в журнал прохождения clean-build. Без записи
в `.orchestra/clean-build-log.md` задача не считается сданной — даже если
все проверки прошли в рабочем дереве.

```sh
script/clean-build.sh --record
```

Скрипт пишет квитанцию `clean-build-receipt.md` в worktree и добавляет
её содержимое в журнал. Worktree после прогона удаляется, если не
передан `--keep`. Проваленный прогон в журнал не пишется — чините
и прогоняйте заново.

## Ограничения

- Полный прогон typecheck всех пакетов требует памяти: на машине с 8 ГБ
  он может упасть по OOM (известное ограничение машины, а не скрипта).
  На маленькой машине используйте `--smoke`, а полный прогон — на машине
  с >= 16 ГБ.
- Скрипт не трогает живой сервер и рабочую базу: worktree — это только
  код, `bun install` и проверки внутри временной папки.
